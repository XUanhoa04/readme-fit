# GitHub Profile README review

Evaluate only the identity communicated by public evidence. Never infer a person’s actual ability, identity, employment, or private experience.

## Workflow

1. Run `npx readme-fit profile <github-user> --format json` when network access is available.
2. Read the profile README, public bio, repository descriptions, topics, languages, and selected public repository READMEs when accessible.
3. State whether pinned repositories were actually available. Do not silently treat recent repositories as pinned.
4. Identify recurring public themes from repository purpose and descriptions; raw language counts are supporting evidence only.
5. Compare headline claims with visible support using `strong`, `moderate`, `limited`, or `not evaluated`. Describe support, not truth.
6. Recommend a hierarchy such as positioning, current work, two or three flagship repositories, focus areas, selected technologies, contact.

## Rubric

- Positioning — 20
- Proof of Work — 25
- Project Selection — 20
- Scanability — 15
- Technical Narrative — 15
- Contact / Next Step — 5

## Skill walls

Do not assume many technology icons are bad. Report an issue when they occupy substantial attention while inspectable project evidence arrives later or is absent. Prefer proof-of-work before decoration.

Use this disclaimer in substance:

> This review describes what the public GitHub profile visibly demonstrates. It does not measure the person’s actual skills or professional experience.
