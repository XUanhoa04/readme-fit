# Project-type rubrics

Use the closest primary type and only relevant secondary types. Treat omitted optional items as `N/A`, not failures.

## CLI and developer tool

Critical: clear outcome, installation, first command, runtime/platform requirement, representative terminal result. Useful: configuration, CI usage, compact GIF. Optional: logo and architecture diagram.

## Library and SDK

Critical: problem solved, installation, minimal code example, expected result, supported runtime/version. High value: API overview, examples, compatibility. A video, hero banner, or logo is normally optional and must not reduce the score when absent.

## API

Critical: purpose, authentication or local setup, first request, representative response, runtime/deployment requirement. High value: endpoint overview, errors, limits, examples.

## Web, desktop, and mobile app

Critical: visible product demonstration, install/download or live route, supported platform, core workflow. Screenshots carry more onboarding weight than they do for a small library.

## GitHub Action and extension

Critical: marketplace/install route, minimal configuration, event or activation context, supported inputs, visible result. Verify referenced action/manifest metadata.

## AI model

Critical: purpose, source, requirements, usage, limitations, license, and evaluation context. Do not infer model quality from a model card’s existence.

## AI agent

Critical: intended task, setup, tool or permission requirements, minimal run, observable output, limitations, and safety boundaries.

## Dataset

Critical: contents, provenance, schema, access, license, intended use, and limitations.

## Template, tutorial, or documentation

Critical: intended outcome, prerequisites, use path, and what the user will have at completion. Avoid demanding product screenshots when the artifact itself is the documentation.

## Infrastructure

Critical: purpose, prerequisites, deployment path, environment assumptions, safety/cost implications, and teardown guidance where relevant.
