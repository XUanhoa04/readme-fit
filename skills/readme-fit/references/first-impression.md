# First-impression review

Call this a heuristic, never eye-tracking or user testing.

Review the hero and the smallest amount of content a visitor can scan quickly:

1. **WHAT** — Is the project category and function explicit?
2. **WHY** — Is a pain point, outcome, or reason to care visible?
3. **SEE** — Can the visitor see representative behavior or output?
4. **TRY** — Is a runnable or install path close to the opening?
5. **TRUST** — Are accurate license, testing, CI, release, limitation, or maintenance signals visible?

Use `YES`, `PARTLY`, or `NO`. Cite hero boundaries, first command/demo lines, words before first success, and relevant repository evidence.

Do not impose one universal line or word threshold. A CLI normally benefits from an early runnable command; a complex infrastructure project may need prerequisites first.
